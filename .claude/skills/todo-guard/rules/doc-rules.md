# 문서 작성 규칙 (todo-guard)

슬라이드·보고서·매뉴얼처럼 **사람이 읽는 문서**를 만들 때 적용한다.
대상: `.pptx` `.pdf` `.doc` `.docx` `.txt` `.hwp` `.md`

**문서를 만들거나 고치기 전에 이 파일을 끝까지 읽는다.**
다 쓴 뒤에는 하네스(`scripts/doc-guard.py`)가 검사한다. 규칙은 쓰기 전, 하네스는 쓴 뒤다.

기본값 ON. 끄려면 `.claude/todo-guard.json` 의 `docRules` 를 `false` 로 둔다.

---

# 1. 문체

## 1-1. 서술식 금지

본문에 서술식(문장체)을 쓰지 않는다. 개조식(명사형 종결)만 쓴다.

**금지하는 종결**

- `~습니다` `~ㅂ니다` `~합니다` `~됩니다` `~입니다`
- `~세요` `~십시오` `~하세요`
- `~해요` `~어요` `~아요` `~죠`
- `~한다` `~는다` `~ㄴ다` 같은 평서형

**써야 하는 형태**

- 명사로 종결 - `토큰 절약`, `자동 완성`, `실행 중단`
- `~함` `~됨` `~없음` `~가능` `~불가` `~필요`
- `~할 것` `~하지 말 것`

| 금지 | 사용 |
|---|---|
| 요금은 토큰에서만 발생합니다 | 요금은 토큰에서만 발생 |
| 딱 8개만 외우면 됩니다 | 외울 명령어는 8개 |
| 삭제는 되돌릴 수 없습니다 | 삭제는 되돌릴 수 없음 |
| 파일을 스스로 찾아서 읽는다 | 파일을 스스로 찾아서 읽음 |
| 아래 4줄을 확인하세요 | 아래 4줄 순서대로 확인 |

**예외 2가지만 허용**

- AI 말풍선 안의 대사
- 터미널 실제 출력 문자열 (`경로를 찾을 수 없습니다` 등)

## 1-2. 「안 · 못 + 명사형」 금지

구어다. 끝 글자에 ㅁ 받침이 붙는 형태 전부 해당한다.

| 금지 | 사용 |
|---|---|
| 안 엉킴 | 파일 하나로 처리 |
| 안 깨짐 | 반응형 유지 |
| 안 지저분해짐 | 깨끗하게 유지됨 |
| 안 올라감 | 미반영 |
| 시작조차 못 함 | 시작 자체가 불가 |
| 이전 대화를 못 봄 | 이전 대화 미포함 |

## 1-3. 강조 부사 + 부정 금지

| 금지 | 사용 |
|---|---|
| 전혀 안 만듦 | 미작성 |
| 한 줄도 직접 쓰지 않음 | 직접 작성 없음 |
| 아무것도 안 줌 | 제공 없음 |
| 통째로 안 바뀜 | 변경 없음 |

## 1-4. 구어체·저렴한 표현 금지

전문 문서다.

| 금지 | 사용 |
|---|---|
| 왜 CLI 를 익혀야 하나 | CLI 를 익혀야 하는 이유 |
| 서버에는 화면이 없음 | 서버 환경에는 GUI 가 없음 |
| 버튼이 아니라 명령으로 동작 | 명령 단위 제어를 전제로 설계 |
| 한 번 배우면 안 바뀜 | 학습 자산의 지속성 |
| 이거 두 개가 제일 중요 | (기능명 그대로 제목화) |
| 90%가 이 셋 | 자주 발생하는 오류와 조치 |
| 데브옵스 | DevOps |

`그냥` `진짜` `왕창` `좀` `이거` `얘` `걔` `뭐` `뭘` 을 쓰지 않는다.

# 2. 지칭

## 2-1. 지시대명사 금지

문서는 한 장씩 따로 읽힌다. 「이 폴더」라고 쓰면 어느 폴더인지 알 수 없다.
**목적과 대상을 이름으로 밝힌다.**

`이 · 그 · 저 · 여기 · 거기 · 저기 · 이곳 · 그곳 · 이때 · 그때 · 이런 · 그런 · 이것 · 그것`

| 금지 | 사용 |
|---|---|
| 이 경로로 바뀐 것을 확인 | 프롬프트가 작업 폴더로 바뀐 것을 확인 |
| 이 폴더에만 적용됨 | 열어 둔 폴더에만 적용됨 |
| 그 키는 폐기 | 올라간 키는 폐기 |
| 여기 적은 내용이 그대로 | 프롬프트에 적은 내용이 그대로 |
| 이런 결과가 나왔을까 | 결과가 갈리는 이유 |
| 그 폴더에서 이어서 시작 | 열어 둔 폴더에서 이어서 시작 |
| 이 대화에서 한 일 | 현재 세션에서 한 일 |

조사 「이」(`Google 이 출시`)는 지시대명사가 아니다.

## 2-2. 상투어

**「자리」는 횟수와 무관하게 0회.** 몇 번이든 쓰지 않는다.
한 문서에 17번 나온 적이 있고, 한 건씩 보면 위반이 아니라 문체 검사에 안 걸렸다.

뜻이 흐릿해 말버릇이 되기 쉬운 낱말은 한 문서에 8회를 넘기지 않는다.

```
부분 경우 상황 지점 대목 측면 모습 존재 위주 바탕 차원 관점
사항 내역 여부 정도 범주 영역 느낌 식으로
```

「기반 · 방식 · 형태 · 요소 · 개념」은 기술 문서의 정상 용어라 뺀다.

## 2-3. 약어는 첫 등장 시 풀네임 병기

`CLI (Command Line Interface)` 처럼 처음 한 번만 병기하고, 이후에는 약어만 쓴다.

# 3. 제목

## 3-1. 제목은 명사구로 쓴다

카드 제목·띠 제목·슬라이드 제목 모두 해당한다.

| 금지 | 사용 |
|---|---|
| 지금 있어야 할 폴더 | 작업 폴더 |
| 맞는지 확인하는 법 | 확인 방법 |
| 무엇을 대신해 주나 | 대신해 주는 작업 |
| 더 있다 | 그 밖의 이벤트 |
| 끄고 싶으면 | 해제 방법 |
| 지금 칠 것 | 실습 준비 |
| 왜 이렇게? | 새 폴더를 쓰는 이유 |
| 어디서 쓰나 | 사용 위치 |

**금지 형태**

- 의문형 - `~인가` `~할까` `~나요` `~주나` `?`
- 서술 종결 - `~있다` `~한다` `~된다` `~않다`
- 관형절 구어 - `~하는 법` `~해야 할 X` `지금 ~` `무엇을 ~` `어떻게 ~`

## 3-2. 한글 수사를 쓰지 않는다

「여덟 개」가 아니라 「8개」. `둘 셋 넷 다섯 여섯 일곱 여덟 아홉 열 스물 서른` + 단위.

---

# 4. 기호

## 4-1. 쓰기 어려운 특수문자 금지

수강생이 따라 칠 수 없거나 글꼴에 따라 깨진다.

- `→ ← ↑ ↓` 는 `>` `<` 로
- `▶ ◀ ● ▲` 같은 도형 문자는 본문에 쓰지 않는다
- `✓ ✔ ●` 는 창 안 답변 표시로만 쓴다

## 4-2. 불릿은 대시만

`-` 만 쓴다. `*` `•` `◦` 를 섞지 않는다.

---

# 5. 배치

## 5-1. 한두 글자 때문에 줄이 넘어가게 두지 않는다 (강력 규칙)

박스 폭을 조금 넘겨 마지막 한두 글자만 다음 줄로 내려가는 배치를 허용하지 않는다.
`Enter` 하나가 혼자 둘째 줄에 남는 것도 안 된다.

**해결 순서**

1. **문구를 줄인다** — 없어도 뜻이 통하는 조사·부사·중복어를 뺀다
2. 줄바꿈 위치를 의미 단위로 직접 지정한다
3. 글꼴 축소나 박스 확대는 마지막 수단

**눈으로 훑지 않는다. 검사로 판정한다.**

## 5-2. 여백을 남기지 않는다

- 내용이 없는 페이지를 만들지 않는다
- 판이 아래까지 안 차면 항목을 늘리거나 판 높이를 줄인다
- 창 높이를 고정값으로 두면 내용이 적을 때 아래가 통째로 빈다

## 5-3. 캡처는 크게 넣는다

- 캡처 한 장은 슬라이드 하나에 크게 넣는다. 4분할로 욱여넣지 않는다
- 세로로 긴 화면은 둘로 잘라 좌우로 배치한다
- 캡처 아래 빈 바탕은 잘라낸다. 그대로 두면 작게 들어간다

---

# 6. 정직성

## 6-1. 지어내지 않는다

- 캡처는 **실제로 실행한 화면**만 쓴다. 목업을 캡처라고 부르지 않는다
- 수치는 **실측값**만 쓴다. 「p95 138ms」라고 적으려면 실제로 재야 한다
- 문서에 적힌 파일·명령·경로가 실제로 있어야 한다.
  실습에 없는 파일(`bench.py` 같은 것)을 만들어 넣지 않는다
- 화면 캡처의 내용과 슬라이드 설명이 어긋나면 안 된다

## 6-2. 숫자는 실제와 맞춘다

프롬프트 줄 수, 항목 개수, 파일 개수를 적었으면 실제와 대조한다.
「21줄」이라 적고 실제가 32줄이면 수강생이 잘못 따라 한다.

## 6-3. 결과물과 문서를 함께 고친다

프롬프트나 사양을 고치면 그것을 가리키는 표·목차·요약도 같이 고친다.
한쪽만 고치면 두 곳이 어긋난 채로 남는다.

---

# 7. 검사 예외

아래는 문체 규칙 대상이 아니다. 화면에 그대로 찍히는 것이기 때문이다.

- 터미널 출력 원문
- AI 응답 말풍선 원문
- 오류 메시지 원문
- 명령·경로·코드 (고정폭 글꼴로 찍은 것)
- 한글이 없는 영문 화면 문구
